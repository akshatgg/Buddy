# Buddy in the notch — Implementation Plan

> **For agentic workers:** three tasks run in parallel on their own branches and worktrees (`notch-a`, `notch-b`,
> `notch-c` from `notch`), each touching only its own files, meeting through the contracts below. Do not change a
> name, a shape or a channel; if a contract is wrong, stop and report. Tests first, `npm test` green, commit often.

**Goal:** On a Mac with a notch, Buddy's eyes peek out either side of the camera; a click drops the chat under the
notch; what Buddy says slides out beside the notch. Spec: `docs/superpowers/specs/2026-10-08-buddy-in-the-notch-design.md`.

**Architecture:** a new see-through window above the menu bar (`notch-window.js`) with its own 2-D page
(`src/renderer/notch/`), chosen over the floating buddy by `home.js`, which main.js uses in the floating buddy's place
(it forwards the whole floating interface, so nothing else in main changes). Pure geometry in `notch-geometry.js`;
the helper tells where the notch is.

**Tech Stack:** Electron 44, CommonJS main, vanilla renderer (CSP: no inline scripts, no remote), `node --test`, ESLint,
Swift helper (`src/native/BuddyHelper.swift`, built by `npm run build:helper`).

## Contracts

### G. Geometry (`src/main/notch-geometry.js`, pure; Task A)

```js
const REACH = 316;   // how far the window reaches past the notch on each side: WING_HOVER + SAY_MAX
const DROP = 8;      // room under the notch for the celebrate bounce
const WING = 44, WING_HOVER = 56, SAY_MAX = 260, CORNER = 12;
// The window: fixed size, so it never resizes; the page draws the smaller black shape inside it, centred.
notchWindowBounds(notch) → { x: notch.x - REACH, y: notch.y, width: notch.width + 2 * REACH, height: notch.height + DROP }
// The chat panel under the notch: centred on it, its top at the work area's top, kept inside the work area.
panelUnderNotch(notch, area, size = PANEL /* from ./geometry */) → { x, y, width, height }
// The Electron display whose bounds equal entry.screen (within 1 pt), else null.
findDisplay(entry, displays) → display | null
// 'notch' when platform === 'darwin' && home === 'notch' && notches.length > 0, else 'floating'.
chooseHome({ platform, home, notches }) → 'notch' | 'floating'
```

### H. The helper (Task A)

Swift: `case "notch": result = notchInfo()` → `{ notches: [{ screen: {x,y,width,height}, notch: {x,y,width,height} }] }`
in Electron points (origin: the primary screen's top-left, y down): for each `NSScreen` with `safeAreaInsets.top > 0`
(guarded by `if #available(macOS 12.0, *)`), `screen` = its frame converted (`y = primary.frame.maxY - frame.maxY`),
`notch` = from `auxiliaryTopLeftArea.maxX` to `auxiliaryTopRightArea.minX`, `safeAreaInsets.top` tall, at
`screen.y`. Empty list otherwise. JS: `helper.call('notch')` (default timeout). Any failure → treated as no notch.

### W. The notch window (`src/main/notch-window.js`; Task A) and its page (Task B)

```js
createNotchWindow({ screen, BrowserWindow = require('electron').BrowserWindow }) → {
  window(), show(notch, display), hide(), isVisible(), destroy(),
  mood(name), say(text), pause(bool), setHover(bool), notch() /* the notch rect shown, or null */,
}
```
- `show(notch, display)` creates the window if needed (type `panel`, transparent, frameless, no shadow, not
  resizable, not focusable, alwaysOnTop level `'screen-saver'`, visible on all workspaces incl. full screen,
  skipTaskbar, `setIgnoreMouseEvents(true, { forward: true })`, preload `src/preload/notch.js`, sandbox +
  contextIsolation, `backgroundThrottling: false`), sets `notchWindowBounds(notch)`, loads
  `src/renderer/notch/index.html`, shows inactive. Messages to a page that is not loaded yet: only the latest mood is
  kept and sent on load (as the floating buddy window does); the layout is always sent on load.
- A cursor timer (66 ms) sends `notch:cursor { dx, dy }` from the window's centre while visible, as the floating
  buddy's `buddy:cursor`.
- Crash/failed load: log and reload once per minute at most; nothing else.

Main → page (`src/preload/notch.js` exposes `window.notch`):
```js
onLayout(fn)  // 'notch:layout' { notchWidth, notchHeight, reach: REACH, drop: DROP, wing: WING, wingHover: WING_HOVER, sayMax: SAY_MAX, corner: CORNER }
onMood(fn)    // 'notch:mood' name
onSay(fn)     // 'notch:say' text
onPause(fn)   // 'notch:pause' bool
onCursor(fn)  // 'notch:cursor' { dx, dy }
```
Page → main: `hover(over)` → `send('notch:hover', bool)`; `click()` → `send('notch:click')`.
`src/main/ipc/notch.js`: `registerNotchIpc({ ipcMain, notch, onClick })`: accepts these only from the notch window's
webContents (`notch.window()?.webContents.id`); hover → `notch.setHover(over)`; click → `onClick()`.

### M. Home (`src/main/home.js`; Task A)

```js
createHome({ floating, notch, bubble, store, helper, screen, platform = process.platform }) → {
  // everything the floating buddy exposes, forwarded to it (show hide isVisible bounds display mood pause
  // reloadModel setHover beginDrag dragTo endDrag resize reclamp window), EXCEPT:
  show(), hide(), isVisible(), mood(name), pause(bool)   // go to the one in use (notch or floating)
  say(text),            // notch: notch.say(text); floating: bubble.say(text, floating.bounds(), floating.display().workArea)
  panelAt(),            // { kind: 'below', notch, area } | { kind: 'beside', buddy: floating.bounds(), area: floating.display().workArea }
  where(),              // 'notch' | 'floating'
  hasNotch(),           // a notch screen is on now (from the last refresh)
  async refresh(),      // asks the helper for `notch`, re-chooses (chooseHome with store.get('home')); if the choice
                        // or the notch moved and the buddy is shown, hides the one not in use and shows the other
                        // (notch.show(notch, display) / floating.show()); keeps the wanted visibility
}
```
- `isVisible()` means "wanted shown" as the one in use reports it. `show()` when the choice is notch never creates the
  floating window. `refresh()` is called by main at start (before the first show), on `display-added` /
  `display-removed`, and by Settings when `home` changes. A helper failure → floating.

### S. Store and Settings (Task A for the IPC; Task C for the page)

- `store.js` DEFAULTS: `home: 'notch'`.
- `ipc/settings.js`: `SETTABLE` gains `'home'`; not `'notch'`/`'floating'` → `BuddyError('bad_request', 'Unknown home.')`;
  after `store.set`, if `home` changed → `await home.refresh()`. The snapshot gains `home` and `hasNotch`
  (`home.hasNotch()`). `registerSettingsIpc` gets `home` in its deps (optional; without it `hasNotch` is false).
- Settings page (Task C): in Buddy, under Size, a row "Where Buddy lives" with a segmented radiogroup `id="home"`
  (`In the notch` / `Floating`), status `id="home-status"`, the whole row hidden unless `snap.hasNotch`. Saved as Size is.

### P. The panel under the notch (`src/main/panel-window.js`; Task C)

`show(state, at)` where `at` is `panelAt()`'s shape: `'beside'` → `panelBounds(at.buddy, at.area)` (as today);
`'below'` → `panelUnderNotch(at.notch, at.area)`. main.js (Task A) calls `panel.show(state, buddy.panelAt())`.

  object main returns) — one line. main.js returns `home` as `buddy` (the home object) — name it `home` in the return.
- `test/e2e/checks/18-notch.js`: before anything, `ctx.helper.replies.notch = { notches: [{ screen: display.bounds,
  notch: { x: cx - 90, y: display.bounds.y, width: 180, height: 32 } }] }`, `ctx.store.set({ home: 'notch' })`,
  `await ctx.home.refresh()`, `ctx.home.show()`: the notch window is visible at `notchWindowBounds`, the floating
  buddy window is not visible; the page: `window.__notchReady === true`; `ctx.home.mood('happy')` → the page's

  `ipcMain.emit`-free: run `window.notch.click()` in the page → the panel opens at `panelUnderNotch`; `ctx.store.set({

## Task B: the notch page

**Files:** create `src/renderer/notch/index.html`, `notch.css`, `notch.js`, `eyes.js` (pure, loaded as a plain
script and `require`d by tests as `src/renderer/panel/chat-view.js` is), `src/renderer/notch/package.json` if the
panel page has one for the module type; test `test/notch-eyes.test.js`.

- The page draws, centred in the window: the black shape (the notch's rectangle plus the wings, rounded bottom
  corners `corner`), the eyes, the say text. Layout from `notch:layout` (W). `document.body.dataset.mood` is the mood
  name; `window.__notchReady = true` once laid out. `#say` holds the text (`hidden` when none).
- `eyes.js`: `createEyes()` → `{ setMood(name, t), setLook(dx, dy), setHover(on), frame(t) }`, `frame(t)` →
  `{ left: { open, arch, droop, tilt }, right: {...}, bounce, dot, done }` all 0..1 (tilt in degrees), with the
  timings of spec §4 (happy 1.2 s, celebrate two bounces within 1.2 s, sad 2.5 s, wave: a 300 ms wink of the right
  eye; blink 120 ms every 3–6 s, seeded by an injectable `random`; look up to 2 pt from `dx, dy` scaled by 1/200,
  clamped). `saying(width, elapsedMs)` → `{ grow: 0..1, hold: bool, done: bool }` for the 220 ms grow, 2.6 s hold,
  220 ms shrink. Unknown moods → idle. The page runs one `setTimeout` loop at 30 fps while something moves and 2 fps
  when idle (blinks wake it), none while paused.
- Hover: the page reports `hover(true)` when the pointer is over the black shape, `false` when it leaves; the wings
  grow to `wingHover`; cursor `pointer`. Click on the shape → `click()`.
- Look: white `#fff` eyes 10 × 14 pt, radius 5; the shape `#000`; the say text `13px -apple-system, system-ui`,
  white, one line, ellipsis, max `sayMax` wide, next to the right eye.
